# Mini Knowledge Assistant

A small internal-support knowledge assistant. Add knowledge articles (policies, FAQs,
troubleshooting notes), ask questions in natural language, and get answers generated by
an LLM, **grounded in the retrieved articles and with source references**.

- **Backend:** Python 3.12, FastAPI (async), PostgreSQL 16 + pgvector, Redis
- **RAG:** structure-aware chunking → `bge-small-en-v1.5` embeddings → HNSW vector
  search → grounded generation with a local LLM (`llama3.2:3b` via Ollama) → cited
  sources
- **Frontend:** React + TypeScript (Vite)
- **Runs fully locally** with Docker Compose. No API keys, no hosted services.
  **Uses an NVIDIA GPU if one is available, and falls back to the CPU automatically.**

Design, trade-offs, failure behaviour and the 10K/100K/1M scaling discussion are in
**[ARCHITECTURE.md](ARCHITECTURE.md)**. AI tool usage is disclosed in
**[AI_USAGE.md](AI_USAGE.md)**.

## Quick start

**Prerequisites:** [Docker Desktop](https://www.docker.com/products/docker-desktop/)
(or Docker Engine + Compose v2.20+), about 10 GB of free disk space, and 8 GB+ RAM.
An NVIDIA GPU is optional.

```bash
git clone <this-repo> && cd <this-repo>

# Windows (PowerShell)
.\scripts\start.ps1

# macOS / Linux
./scripts/start.sh
```

The script checks whether an NVIDIA GPU is usable from Docker and starts the stack in
GPU or CPU mode accordingly. It runs everything in the background and returns once all
services are healthy, printing the URLs and the commands to view logs or stop. Then
open:

| What | URL |
|---|---|
| **Web UI** | http://localhost:5173 |
| API docs (Swagger) | http://localhost:8000/docs |
| Health / readiness | http://localhost:8000/health, http://localhost:8000/ready |

**The first start takes a while:**
- the backend image is built,
- the Ollama image is pulled,
- the LLM (`llama3.2:3b`, about 2 GB) is downloaded into a Docker volume.

The model is then warmed up (loaded into memory) before the backend starts, so the first
question is answered quickly. Later starts take seconds.

To load a few example articles (refund policy, VPN troubleshooting, password reset and
others) once the backend is up:

```bash
docker compose exec backend python -m scripts.seed
```

## Run modes

| Mode | Command | When to use |
|---|---|---|
| **Auto (recommended)** | `.\scripts\start.ps1` / `./scripts/start.sh` | GPU if usable, otherwise CPU |
| Force CPU | `start.ps1 -Cpu` / `start.sh --cpu` | Test the CPU path on a GPU machine |
| **Demo (no LLM)** | `start.ps1 -Mock` / `start.sh --mock` | No 2 GB model download. Real embeddings and retrieval; the "answer" quotes the top passages and is clearly labelled `[DEMO MODE]` |
| Foreground (stream logs) | add `-Attach` / `--attach` | Watch all service logs live; Ctrl+C stops the stack |

Equivalent raw Compose commands:

```bash
docker compose --profile llm up --build                                              # CPU
docker compose -f docker-compose.yml -f docker-compose.gpu.yml --profile llm up --build  # NVIDIA GPU
LLM_PROVIDER=mock docker compose up --build                                          # demo mode
```

**How the GPU/CPU choice works.**
1. The start script checks `nvidia-smi` and `docker run --gpus all`. If both work, it
   adds `docker-compose.gpu.yml`, which passes the GPU to the backend and Ollama and
   builds the backend with CUDA PyTorch.
2. Inside the backend, `app/core/device.py` uses CUDA if `torch.cuda.is_available()`
   and the CPU otherwise. It never crashes on a CPU-only machine.

The active device is shown in the UI header and in `GET /health`.

Stop everything with `docker compose --profile llm down`. Add `-v` to also delete the
database and the downloaded model.

## Using the app

1. Open http://localhost:5173 → **Knowledge base** tab → add an article (or run the
   seed command above).
2. Go to the **Ask** tab and ask, for example, *"How long do I have to request a refund?"*
3. The answer shows its **sources**. Sources the model cited are highlighted, and each
   one shows a relevance score.

The UI also shows:
- a loading state,
- an error state with a request reference id,
- a retry countdown when rate limited (20 questions per minute),
- a notice when nothing relevant was found.

## API

Interactive docs: http://localhost:8000/docs (OpenAPI). Main endpoints:

| Method | Path | Purpose | Success |
|---|---|---|---|
| `POST` | `/documents` | Add an article: validate, chunk, embed, index | `201` `{document_id, status: "indexed", chunk_count, created_at}` |
| `GET` | `/documents?limit=20&offset=0` | List articles, newest first | `200` `{items: [{document_id, title, status, chunk_count, created_at}], total, limit, offset}` |
| `POST` | `/ask` | Ask a question (rate limited: 20/min per client) | `200` `{question_id, answer, sources: [...], grounded, mode, model, latency_ms}` |
| `GET` | `/documents/{id}` | One article including its content | `200` |
| `DELETE` | `/documents/{id}` | Delete an article and its chunks | `204` |
| `GET` | `/health` | Liveness, plus active device and models | `200` |
| `GET` | `/ready` | Readiness: DB, Redis and LLM checks | `200` / `503` |

Examples:

```bash
# Add a document
curl -s -X POST http://localhost:8000/documents \
  -H "Content-Type: application/json" \
  -d '{"title": "Refund Policy", "content": "Customers can request a full refund within 30 days of purchase. Refunds are issued to the original payment method within 5 business days."}'

# List documents
curl -s "http://localhost:8000/documents?limit=10&offset=0"

# Ask a question
curl -s -X POST http://localhost:8000/ask \
  -H "Content-Type: application/json" \
  -H "X-Client-Id: my-client-0001" \
  -d '{"question": "How long do I have to request a refund?"}'
```

Example `/ask` response:

```json
{
  "question_id": "8f0c...",
  "answer": "You can request a full refund within 30 days of purchase [1].",
  "sources": [
    {
      "document_id": "2b1e...",
      "title": "Refund Policy",
      "chunk_id": "c4d2...",
      "chunk_index": 0,
      "snippet": "Customers can request a full refund within 30 days of purchase...",
      "score": 0.8123,
      "cited": true
    }
  ],
  "grounded": true,
  "mode": "llm",
  "model": "llama3.2:3b",
  "latency_ms": 2140
}
```

`mode` is one of:
- `llm`: a real model answered.
- `demo`: mock fallback; no model was called.
- `no_context`: nothing relevant was retrieved, so the LLM was not called and the
  answer says so.

**Errors** always use one envelope; `request_id` matches the `X-Request-ID` header and
the server logs:

```json
{"error": {"code": "RATE_LIMITED", "message": "Too many requests. Please slow down.", "request_id": "5e1a...", "details": {"retry_after_seconds": 42}}}
```

Status codes:
- `422` validation (with field details)
- `404` unknown document
- `409` duplicate content
- `413` body over 1 MB
- `429` rate limited, with `Retry-After`
- `503` dependency unavailable (`LLM_UNAVAILABLE`, `LLM_RATE_LIMITED`, `LLM_BUSY`,
  `LLM_MODEL_NOT_READY`, `DATABASE_UNAVAILABLE`, `EMBEDDING_UNAVAILABLE`)
- `504` LLM timeout

See [ARCHITECTURE.md §8](ARCHITECTURE.md#8-error-handling-and-failure-behaviour).

## Running tests

The tests use the real PostgreSQL + pgvector (a separate `knowledge_test` database).
For speed and determinism they use the hash embedder and fake or mocked LLMs. Upstream
behaviour (timeouts, 5xx, 429 + `Retry-After`, missing model) is simulated with
`httpx.MockTransport`.

```bash
# with the stack running (any mode)
docker compose exec backend pytest

# or as a one-off container (starts db and redis if needed)
docker compose run --rm backend pytest -q
```

What is covered:
- validation of every endpoint (empty, whitespace-only, oversized, unknown fields, bad
  pagination)
- document ingestion, duplicates, pagination and delete
- `/ask` grounding, citations, `no_context` without an LLM call, and question history
- error mapping (503/504 envelopes without internal details), including a database
  that is unreachable (connection refused or unknown host)
- the DB connection being released while the LLM generates (single-connection pool)
- LLM retries, backoff bounds, timeouts, upstream 429 handling and concurrency
  backpressure
- rate limiting (429 + `Retry-After`, per-client isolation, Redis shared across
  instances, fail-open)
- chunking edge cases

Frontend type check and production build: `cd frontend && npm ci && npm run build`.

## Running without Docker

Useful for development. PostgreSQL and Redis still run in Docker; the backend and
frontend run on the host.

```bash
docker compose up -d db redis                 # Postgres on localhost:5433, Redis on localhost:6380

# Backend (Python 3.11+)
cd backend
python -m venv .venv && . .venv/bin/activate  # Windows: .venv\Scripts\activate
# PyTorch: pick ONE
pip install torch==2.7.1 --index-url https://download.pytorch.org/whl/cpu     # CPU
pip install torch==2.7.1 --index-url https://download.pytorch.org/whl/cu126   # NVIDIA GPU
pip install -r requirements.txt -r requirements-dev.txt
alembic upgrade head
uvicorn app.main:app --reload --port 8000

# LLM: install Ollama from https://ollama.com and run `ollama pull llama3.2:3b`,
# or set LLM_PROVIDER=mock for demo mode.

# Frontend (Node 20+)
cd frontend
npm ci
npm run dev                                   # http://localhost:5173 (proxies /api to localhost:8000)

# Tests
cd backend && pytest
```

## Configuration

All settings are environment variables with working defaults; see
[`.env.example`](.env.example). Compose reads a root `.env`. The natively-run backend
reads `backend/.env` or the environment. The most useful ones:

| Variable | Default | Description |
|---|---|---|
| `LLM_PROVIDER` | `ollama` | `ollama` (real model) or `mock` (demo fallback) |
| `LLM_MODEL` | `llama3.2:3b` | Any Ollama model tag, e.g. `qwen2.5:7b` for better answers on a GPU |
| `LLM_TIMEOUT_S` | `120` | LLM read timeout (CPU generation is slow) |
| `LLM_MAX_RETRIES` | `2` | Retries for transient LLM failures (bounded) |
| `LLM_MAX_CONCURRENCY` | `4` | Concurrent LLM calls per instance; beyond this, requests wait up to `LLM_QUEUE_TIMEOUT_S`, then get 503 |
| `EMBEDDING_PROVIDER` | `local` | `local` (bge-small) or `hash` (no-download lexical fallback) |
| `EMBEDDING_DEVICE` | `auto` | `auto` / `cuda` / `cpu` |
| `RETRIEVAL_TOP_K` | `4` | Chunks retrieved per question |
| `RETRIEVAL_MIN_SCORE` | provider default | Relevance cut-off (cosine similarity) |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | `800` / `150` | Chunking, in characters |
| `ASK_RATE_LIMIT_PER_MINUTE` | `20` | Per-client limit on `POST /ask` |
| `RATE_LIMIT_BACKEND` | `redis` | `redis` (shared across instances) or `memory` (single process) |
| `RATE_LIMIT_FAIL_OPEN` | `true` | Allow requests if Redis is down (logged) |
| `DATABASE_URL` | `postgresql+asyncpg://knowledge:knowledge@localhost:5433/knowledge` | |
| `REDIS_URL` | `redis://localhost:6380/0` | |
| `LOG_LEVEL` / `LOG_JSON` | `INFO` / `true` | Structured JSON logs to stdout |
| `POSTGRES_PORT`, `REDIS_PORT`, `BACKEND_PORT`, `FRONTEND_PORT`, `OLLAMA_PORT` | `5433`, `6380`, `8000`, `5173`, `11434` | Host ports, if the defaults are taken |

No secrets are required. The database password in `docker-compose.yml` is a local
development credential only.

## Git workflow

| Branch | Purpose |
|---|---|
| `main` | Released, stable code |
| `staging` | Release candidate; promoted to `main` after verification |
| `development` | Integration branch; features are merged here first |
| `feature/*` | One branch per feature, branched from and merged back into `development` (`--no-ff`) |
| `bugfix/*` | Fixes for defects found during integration, merged into `development` |

Flow: `feature/*` / `bugfix/*` → `development` → `staging` → `main`.

## Troubleshooting

- **"port is already allocated".** Another program uses that port. Set e.g.
  `POSTGRES_PORT=5434` in a root `.env`. Defaults avoid the standard 5432/6379 for this
  reason.
- **First answer is slow or times out on CPU.** The model loads into memory on first
  use. Retry once, use the GPU, or try demo mode (`-Mock`).
- **`LLM_MODEL_NOT_READY`.** The model download (`ollama-init`) hasn't finished. Check
  with `docker compose logs -f ollama-init`.
- **GPU not detected.** Make sure `docker run --rm --gpus all busybox true` works.
  On Windows this needs Docker Desktop with the WSL2 backend and a current NVIDIA
  driver; on Linux it needs `nvidia-container-toolkit`.
- **`pip` cannot reach pypi.org during the image build** (blocked networks). Set
  `PIP_INDEX_URL=<a mirror you trust>` in a root `.env` and rebuild.
